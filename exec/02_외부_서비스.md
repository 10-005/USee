# USee 외부 서비스 정보

기준일: 2026-11-18. 키·토큰 값은 이 문서에 적지 않는다. 값이 들어가는 위치와 발급 방법만 적는다.

| Naver Cloud Maps | 지도 표시, 주소 검색(지오코딩) | 모바일, core-api | 모바일 `AndroidManifest.xml`, SealedSecret `core-api-secrets` |

소셜 로그인은 Kakao 하나만 쓴다. 공공데이터 API는 실행 중에 호출하지 않는다(행정구역 목록은 시드 SQL에 들어 있다).

## 2. Kakao 로그인

- 가입: [Kakao Developers](https://developers.kakao.com)에서 애플리케이션을 만들고 Android 플랫폼(패키지 `com.usee.animal`, 키 해시)을 등록한다. 카카오 로그인을 활성화한다.
- 동작: 앱이 Kakao SDK로 액세스 토큰을 받아 core-api에 보낸다. core-api는 `https://kapi.kakao.com/v1/user/access_token_info`로 토큰을 검증하고, 다른 앱에서 발급한 토큰은 앱 ID로 걸러낸다. 인가 코드 교환은 하지 않는다.
- 설정:
  - 모바일: `mobile/android/local.properties`의 `KAKAO_NATIVE_APP_KEY`(네이티브 앱 키). 없으면 빌드가 실패한다.
  - core-api: 환경 변수 `KAKAO_APP_ID`(앱 ID, 숫자). 기본값이 `application.yml`에 있다. 다른 Kakao 앱을 쓰면 이 값을 바꾼다.
- 키 해시는 서명 키스토어마다 다르다. 현재 릴리스 APK는 디버그 키스토어로 서명하므로 그 해시를 등록한다.

## 3. Naver Cloud Maps

- 가입: [Naver Cloud Platform](https://www.ncloud.com) 콘솔 → AI·NAVER API → Application 등록. Dynamic Map(모바일), Geocoding·Reverse Geocoding(서버)을 선택하고 Android 패키지 `com.usee.animal`을 등록한다.
- 모바일: `AndroidManifest.xml`의 meta-data `com.naver.maps.map.NCP_KEY_ID`에 클라이언트 ID를 넣는다.
- core-api: 주소 검색에 `https://maps.apigw.ntruss.com/map-geocode/v2/geocode`를 호출한다. 헤더 `x-ncp-apigw-api-key-id`, `x-ncp-apigw-api-key`.
  - SealedSecret `core-api-secrets`의 `NAVER_MAP_CLIENT_ID`, `NAVER_MAP_CLIENT_SECRET`
  - 등록 스크립트: `infra/scripts/add-naver-map-keys.sh`
  - 키가 비어 있으면 주소 검색 API가 503을 돌려준다.

## 4. Firebase Cloud Messaging

- 가입: [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 만들고 Android 앱(패키지 `com.usee.animal`)을 추가한다.
- 모바일: 내려받은 `google-services.json`을 `mobile/android/app/`에 둔다. 알림 채널 이름은 `usee_push`다. 상세는 `mobile/docs/FCM.md`.
- notification: 프로젝트 설정 → 서비스 계정 → 새 비공개 키 생성으로 받은 JSON 전체를 SealedSecret `notification-secrets`의 `FIREBASE_CREDENTIALS`에 넣는다. 비어 있으면 푸시를 보내지 않고 로그로만 남긴다.
- 기기 토큰은 앱이 `/api/notification/v1/notifications/device-tokens`로 등록한다.
- iOS는 설정하지 않았다.

## 5. OpenAI API

- 가입: [OpenAI Platform](https://platform.openai.com)에서 API 키를 발급하고 결제 수단을 등록한다.
- 용도: 모의 입양(7일) 종료 리포트의 요약 문단을 만든다. `POST https://api.openai.com/v1/chat/completions`, 모델 `gpt-6-luna`, 타임아웃 20초.
- 설정: SealedSecret `simulation-secrets`의 `OPENAI_API_KEY`. 등록 스크립트는 `infra/scripts/add-openai-key.sh`.
- 키가 없거나 호출이 실패하면 규칙 기반 문구로 대체되어 리포트 자체는 만들어진다.
- 보내는 내용은 서버가 집계한 근거 문장 후보와 안내 문서 맥락뿐이다. 회원 정보와 원본 이력은 보내지 않는다.
- 비용: 리포트 1건에 약 4,700토큰, 약 0.001달러(2026-11-16 측정).

## 6. AWS

AWS 계정 하나를 쓴다. 리전은 `ap-northeast-2`, 로컬 프로파일 이름은 `s15p31d106`이다. Lightsail(노드 1)을 뺀 리소스는 `infra/terraform`으로 만든다.

| 리소스 | 이름 | 용도 | 접근 |
|---|---|---|---|
| Lightsail 인스턴스 | (노드 1) | k3s server | 콘솔에서 수동 생성 |
| EC2 | `k15d106-node2` (`t3.large`) | k3s agent, CI 빌드 | Terraform `node2.tf` |
| S3 버킷 | `s15p31d106-media-887324111755` | 사진 업로드, AI 모델(`models/`) | 비공개. IAM 사용자 `core-api-media` |
| S3 버킷 | `s15p31d106-backup-887324111755` | PostgreSQL 백업(`postgres/`), 30일 보관 | IAM 사용자 `backup-writer`(쓰기만 가능) |
| S3 버킷 | `s15p31d106-tfstate-887324111755-ap-northeast-2-an` | Terraform 상태 | 관리자 |
| CloudFront | `https://d2cxge8l3dd66.cloudfront.net` | 미디어 버킷 읽기(OAC) | 공개 |
| Budgets | `s15p31d106-monthly` | 월 예산 알림 | |

- 업로드 흐름: 클라이언트가 core-api에서 Presigned PUT URL(유효 10분)을 받아 S3에 직접 올린다. 조회는 CloudFront 주소로 한다.
- IAM 키 발급: `infra/scripts/gen-core-api-s3-secrets.sh`, `gen-backup-secrets.sh`가 키를 만들고 SealedSecret으로 암호화한다. IAM 사용자당 키는 2개까지라서 이미 2개면 스크립트가 실패한다.
- AI 모델을 받는 CI용 키는 GitLab CI 변수 `AI_MODELS_AWS_ACCESS_KEY_ID`, `AI_MODELS_AWS_SECRET_ACCESS_KEY`에 둔다.
- 다른 AWS 계정으로 옮기면 버킷 이름(계정 ID 포함)과 CloudFront 주소가 바뀐다. 서비스 Deployment의 `STORAGE_BUCKET`, `STORAGE_PUBLIC_BASE_URL`, `IMAGE_URL_PREFIX`를 함께 고친다.

## 7. Tailscale

- 가입: [Tailscale](https://tailscale.com)에서 tailnet을 만들고 팀원을 초대한다.
- 용도:
  - 노드 1(Lightsail)과 노드 2(EC2)를 사설망으로 연결한다.
  - ArgoCD, Grafana, PostgreSQL을 인터넷에 열지 않고 tailnet 안에서만 접근한다.
- 필요한 것:
  - 노드 가입용 인증 키(`tag:k3s`): Terraform 변수 `tailscale_auth_key`
  - Operator용 OAuth 클라이언트(권한: Services, Devices Core, Auth Keys 쓰기, 태그 `tag:k8s-operator`): `infra/scripts/gen-tailscale-oauth-secret.sh`로 SealedSecret `operator-oauth` 생성
  - ACL 태그: `tag:k3s`, `tag:k8s-operator`, `tag:k8s`, `tag:svc-argocd`, `tag:svc-db`

## 8. Vercel

- 가입: [Vercel](https://vercel.com)에서 프로젝트를 만든다.
- 웹 CI(`web/.gitlab-ci.yml`)가 `develop-web` push 때 빌드 결과를 올리고 `s15p31d106-develop-web.vercel.app`으로 별칭을 건다.
- 설정: GitLab CI 변수 `VERCEL_TOKEN`. 조직·프로젝트 ID는 CI 파일에 있다.
- `/api/*`는 `web/vercel.json`의 rewrite로 `https://k15d106.p.ssafy.io/api/*`에 전달된다.
