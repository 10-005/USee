## 1. 시스템 개요

USee는 반려동물 실종·발견·보호·입양 서비스와 모의 입양 시뮬레이션으로 구성된다.

```
모바일 앱(React Native) · 보호소 웹(React, Vercel)
   │ HTTPS 443
   ▼
Traefik (k3s 내장, 80 → 443 리다이렉트, Let's Encrypt)
   ├─ /api/core         ─▶ core-api (Spring :8080)      ─▶ PostgreSQL · Redis · S3
   ├─ /api/chat         ─▶ chat (Spring :8081, WebSocket STOMP)
   ├─ /api/notification ─▶ notification (Spring :8082)  ─▶ FCM
   ├─ /api/simulation   ─▶ simulation (Spring :8083)    ─▶ OpenAI
   ├─ /swagger-ui       ─▶ core-api (문서 허브)
   └─ /v2               ─▶ registry (컨테이너 이미지, 계정 인증)

서비스 간 이벤트: RabbitMQ topic exchange `animal.events`
core-api ─ HTTP ─▶ breed-server (FastAPI :8000, 품종 추천, 클러스터 내부 전용)
core-api ─ MatchRequested ─▶ match-worker(dog·cat) ─ AiMatchFound ─▶ core-api
이미지: 클라이언트 ─ Presigned PUT ─▶ S3(비공개) ─▶ CloudFront(OAC) ─▶ 클라이언트
```

- 클러스터는 k3s 2노드다. 노드 1(AWS Lightsail, k3s server)에 서비스·DB·미들웨어가 모두 있고, 노드 2(AWS EC2 t3.large, k3s agent)는 예비 노드이자 CI 빌드(GitLab Runner) 노드다.
- 두 노드는 Tailscale 사설망으로 연결된다(flannel이 `tailscale0` 인터페이스를 사용).
- 배포는 GitOps다. `infra` 브랜치가 클러스터 상태의 기준이고, 클러스터 안의 ArgoCD가 이 브랜치를 가져와 반영한다.
- 웹은 클러스터가 아니라 Vercel에 배포한다. `/api/*` 요청은 Vercel rewrite로 `https://k15d106.p.ssafy.io/api/*`에 전달된다.

## 4. 환경 변수

값은 Git에 평문으로 두지 않는다. 서버는 SealedSecret과 Deployment의 `env`로, 로컬은 `backend/.env`로 주입한다. 전체 목록은 `05_환경변수_전체목록.md`에 있다. 요약:

| 주입 위치 | 대상 | 내용 |
|---|---|---|
| `backend/.env` (`.env.example` 복사) | 로컬 백엔드 | DB·Redis·RabbitMQ 접속, JWT 키 |
| `infra/services/<서비스>/base/deployment.yaml`의 `env` | 서버 서비스 | 프로파일, DB URL·계정, Redis·RabbitMQ 호스트, 버킷, CORS 등 비밀이 아닌 값 |
| `infra/platform/secrets/*.yaml` (SealedSecret 15개) | 서버 서비스·미들웨어 | DB·Redis·RabbitMQ 비밀번호, JWT 키, 외부 서비스 키 |
| GitLab CI/CD 변수 | CI | `REGISTRY_CI_PASSWORD`, `INFRA_PUSH_TOKEN`, `AI_MODELS_AWS_ACCESS_KEY_ID`, `AI_MODELS_AWS_SECRET_ACCESS_KEY`, `VERCEL_TOKEN` |
| `mobile/android/local.properties` | 모바일 빌드 | `sdk.dir`, `KAKAO_NATIVE_APP_KEY` |
| `infra/terraform/terraform.tfvars` | Terraform | `ssh_allowed_cidrs`, `tailscale_auth_key`, `k3s_token`, `budget_email` |

SealedSecret을 바꾸면 해당 Deployment를 다시 시작해야 값이 반영된다(환경 변수는 파드 생성 때 한 번만 읽는다).

## 5. 로컬 빌드·실행

### 5.1 백엔드

필요 도구: JDK 21, Docker(Compose v2), OpenSSL.

```bash
cd backend
cp .env.example .env            # DB·Redis·RabbitMQ 비밀번호를 직접 채운다

# JWT 키(RS256) 생성 → 출력 값을 .env의 JWT_PUBLIC_KEY / JWT_PRIVATE_KEY 에 넣는다
mkdir -p .keys
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out .keys/jwt-private.pem
openssl pkey -in .keys/jwt-private.pem -pubout -outform DER | base64 | tr -d '\n'
openssl pkcs8 -topk8 -nocrypt -in .keys/jwt-private.pem -outform DER | base64 | tr -d '\n'

docker compose up -d            # postgres:17-alpine, redis:7.4-alpine, rabbitmq:4-management
./gradlew :core-api:bootRun     # 반드시 가장 먼저(Flyway가 core 스키마 테이블을 만든다)
./gradlew :chat:bootRun
./gradlew :notification:bootRun
./gradlew :simulation:bootRun

./gradlew build                 # 빌드 + 테스트
docker compose down -v          # 초기화
```

- 기본 프로파일은 `local`이다. 프로파일은 `local`, `dev` 두 개이고 서버는 `dev`로 띄운다.
- core-api를 먼저 띄운다. chat·notification은 `ddl-auto: validate`라서 core-api의 Flyway가 만든 테이블이 있어야 기동한다.
- `local`·`dev` 프로파일에서는 Flyway가 `db/dev`의 시연용 데이터(SQL)도 넣는다.
- 확인: `http://localhost:8080/actuator/health`, Swagger `http://localhost:8080/swagger-ui`
- 로컬 기본값 `EVENTS_TRANSPORT=log`는 이벤트를 로그로만 남긴다. RabbitMQ로 실제 발행하려면 `rabbit`으로 바꾼다.

이미지 직접 빌드(빌드 컨텍스트는 `backend/`):

```bash
cd backend
docker build -f core-api/Dockerfile -t core-api .
```

### 5.4 AI

모델 가중치는 Git에 없다. CI가 S3(`s3://s15p31d106-media-887324111755/models/`)에서 받아 이미지에 넣는다.

```bash
# breed-server: models/breed/20261110/{dog,cat}/ → ai/breed-server/models/{dog,cat}/
# match-worker: models/reid/20261110/{dog,cat}/  → ai/match-worker/{dog,cat}/models/
cd ai/breed-server && docker build -t breed-server .
cd ai/match-worker && docker build -t match-worker .
```

## 6. CI/CD

### 6.1 흐름

```
MR 머지(develop-backend / develop-ai)
  → GitLab Runner(노드 2): 테스트 → docker build → registry push (태그 = 커밋 SHA 8자리)
  → CI가 infra 브랜치의 newTag 를 커밋
  → ArgoCD가 infra 브랜치 변경을 감지해 클러스터에 반영
```

CI는 클러스터 접속 권한(kubeconfig)을 갖지 않는다. CI가 하는 일은 레지스트리 push와 `infra` 브랜치 커밋뿐이다.

### 6.2 파이프라인

| 파일 | 잡 | 내용 |
|---|---|---|
| `backend/.gitlab-ci.yml` | `backend:test` | `./gradlew build --no-daemon` (develop-backend 대상 MR) |
| | `<서비스>:build` | `docker build -f backend/<서비스>/Dockerfile -t k15d106.p.ssafy.io/animal/<서비스>:$CI_COMMIT_SHORT_SHA backend` 후 push |
| | `<서비스>:deploy` | `infra/services/<서비스>/overlays/dev/kustomization.yaml`의 `newTag`를 바꿔 커밋·push(충돌 시 pull --rebase 3회 재시도) |
| `ai/.gitlab-ci.yml` | `breed-server:*`, `match-worker:*` | S3에서 모델을 받은 뒤 위와 같은 방식으로 빌드·배포 |
| `web/.gitlab-ci.yml` | `web-check`, `web-preview` | `npm run check` 후 `vercel deploy --prebuilt`, 별칭 `s15p31d106-develop-web.vercel.app` |
| `mobile/.gitlab-ci.yml` | `notify-mobile-merge` | 머지 알림만 보낸다. APK 빌드는 CI에 없다(로컬 빌드) |

- 서비스별 잡은 자기 모듈 또는 공통 경로(`common`, `gradle/**` 등)가 바뀔 때만 실행된다.
- CI 커밋 메시지: `chore: deploy <서비스> <sha>`.
- `AI_MODELS_AWS_*` 변수는 Protected라서 `develop-ai`가 보호 브랜치여야 한다.

### 6.3 롤백

`infra` 브랜치에서 해당 배포 커밋을 되돌린다(`git revert`). ArgoCD가 이전 태그로 맞춘다. `kubectl`로 직접 고친 내용은 ArgoCD selfHeal이 되돌리므로 쓰지 않는다.

## 7. 신규 서버 구축 절차

상세 절차와 장애 대응은 `infra/docs/rebuild-runbook.md`에 있다. 순서만 요약한다. 순서가 바뀌면 실패한다.

1. 노드 1 준비: Ubuntu 인스턴스 생성, 방화벽에서 22/tcp, 80/tcp, 443/tcp, 41641/udp 허용.
2. Tailscale 설치. 노드 1의 Tailscale IP가 `100.121.219.58`이 아니면 `infra/bootstrap/k3s-config-node1.yaml`과 Terraform 변수 `k3s_url`을 새 IP로 고친다.
3. `k3s-config-node1.yaml`을 `/etc/rancher/k3s/config.yaml`에 복사하고 k3s v1.36.5+k3s1 server를 설치한다. Tailscale이 먼저 떠 있어야 한다.
4. **Sealed Secrets 마스터 키 복원**: ArgoCD 동기화 전에 `kubectl apply -f sealed-secrets-master.yaml`을 실행한다. 이 키가 없으면 저장소의 SealedSecret 15개를 복호화할 수 없다. 키가 없는 새 환경이면 `infra/scripts/gen-*.sh`로 비밀값을 전부 다시 만든다(8절).
5. ArgoCD v3.5.6 설치(`install.yaml`), 관리자 비밀번호 설정, GitLab 저장소 인증 등록.
6. `kubectl apply -f infra/argocd/root.yaml`. ArgoCD가 22개 Application을 동기화한다.
7. PostgreSQL이 빈 볼륨으로 뜨면 초기화 스크립트가 계정·스키마·확장을 만든다. 덤프를 복원한다(`03_DB_덤프_안내.md`).
8. 레지스트리가 비어 있으면 CI 파이프라인을 수동 실행해 이미지를 다시 올린다. 그 전까지 서비스 파드는 `ImagePullBackOff` 상태다.
9. 노드 2 생성: 노드 1에서 `sudo k3s token create --ttl 24h`, Tailscale 인증 키(`tag:k3s`) 발급 후 `infra/terraform`에서 `terraform plan` → `terraform apply`. 이후 Docker와 GitLab Runner를 수동 설치한다.

노드 1에서 kubectl은 `sudo k3s kubectl`로 실행한다.

## 8. 비밀값 생성

모든 스크립트는 저장소 루트에서 실행하고, `kubeseal --cert infra/platform/sealed-secrets/pub-cert.pem`으로 암호화한 결과만 파일에 쓴다. 평문은 화면·저장소에 남기지 않는다.

| `gen-backup-secrets.sh` | `postgres-backup-s3` | 같음 |
| `gen-chat-notification-secrets.sh` | `chat-secrets`, `notification-secrets`, `rabbitmq-app` | 노드 1 SSH 키, JWT 키 |
| `gen-simulation-secrets.sh` | `simulation-secrets` | 노드 1 SSH 키 |

## 10. 배포 특이사항

1. **클러스터는 Git으로만 바꾼다.** 모든 Application에 `prune`, `selfHeal`이 켜져 있어 `kubectl edit`, `kubectl scale`로 바꾼 내용은 되돌려진다.
2. **`infra` 브랜치에는 CI도 커밋한다.** 사람이 push하기 전에 항상 `git pull --rebase`를 한다.
3. **Sealed Secrets 마스터 키는 저장소에 없다.** 별도 보관본으로 복원한다(7절 4단계). 키는 30일마다 새로 생기므로 백업도 주기적으로 갱신한다.
4. **비밀값 스크립트를 다시 돌리면 일부 키가 빠진다.** `gen-core-api-secrets.sh`는 네이버 지도 키를, `gen-simulation-secrets.sh`는 OpenAI 키를 지운다. 다시 돌린 뒤에는 `add-naver-map-keys.sh`, `add-openai-key.sh`를 이어서 실행한다.
5. **Tailscale이 k3s보다 먼저 떠야 한다.** k3s가 `tailscale0` 인터페이스로 통신한다. 노드 1은 Tailscale 태그가 없어 ACL에 IP를 직접 적어야 한다.
6. **AI 서비스는 노드 1에 고정된다**(`nodeSelector role=primary`). 노드 2는 디스크 여유가 적다. AI 이미지는 2.2GB~3.3GB다.
7. **chat은 레플리카 1개로만 운영한다.** STOMP 브로커가 인메모리라서 2개 이상으로 늘리면 메시지가 다른 파드의 구독자에게 전달되지 않는다.
8. **match-worker는 `Recreate` 전략이다.** 배포 중에는 매칭이 멈추고 요청은 큐에 쌓인다.
9. **서버의 core-api는 `SPRING_JPA_HIBERNATE_DDL_AUTO=update`로 뜬다.** 스키마는 Flyway(`db/migration`)와 이 설정이 함께 관리한다. `dev` 프로파일이라 `db/dev`의 시연 데이터도 들어간다.
10. **외부 서비스 키가 없어도 기동한다.** 키가 비어 있으면 해당 기능만 제한된다: OpenAI(리포트 요약이 규칙 문구로 대체), FCM(푸시를 로그로만 기록), 네이버 지도·breed-server(해당 API가 503).
11. **레지스트리 이미지 정리가 자동이 아니다.** 볼륨은 20Gi다. 가득 차면 push가 실패한다.
12. **PostgreSQL 백업은 6시간마다 S3에 올라간다.** 시점 복구(PITR)는 없다. 복구 지점은 6시간 단위 덤프다.
13. **웹의 접속 도메인이 바뀌면 CORS를 고친다.** 서비스 4개 Deployment의 `CORS_ALLOWED_ORIGINS`와 S3 미디어 버킷 CORS(`infra/terraform/media.tf`)에 새 도메인을 추가한다.
14. **모니터링 알림은 없다.** Alertmanager를 쓰지 않으므로 장애는 Grafana에서 직접 확인한다. 메트릭·로그 보존은 7일이다.
