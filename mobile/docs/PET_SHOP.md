# 상점 1차 구현 — S15P31D106-239

진입: 모의 입양 예산 설정 → 모의 입양 방 → 상단 `상점`.

- 상품 목록: 종별 상품, 필수 준비/카테고리 분류, 이름·설명 검색, 가격 정렬, 빠른 담기.
- 상품 상세: 원본 atlas 이미지, 용도·묶음 수량·보유 수량, 가격 근거·판매처 링크, 수량 선택.
- 장바구니: 선택/전체 선택, 수량 변경, 개별/선택 삭제, 필수 준비 현황, 금액·잔여 예산.
- 모의 구매: 확인 후 선택 상품만 구매, 예산 초과 제한, 묶음을 실제 게임 수량으로 환산하여 보유 물품에 추가.
- 목록에서 한 번에 0~10묶음 선택, 초기값 0. 담기 성공 시 1.5초 토스트 동안 수량 조절·담기를 잠그고 이후 0으로 초기화.
- 장바구니 누적 수량과 재사용 물품 중복 구매 제한 없음. 다른 종의 상품과 종료된 모의 입양의 구매는 차단.
- 남은 예산 옆의 예산 추가 버튼으로 금액을 추가하고 DB에 저장. 총 예산은 기존 예산 입력과 동일하게 최대 1억 원.
- 찾아요와 검색바·필터 버튼 컴포넌트를 공유하며 분류와 가격 정렬 지원. 가격은 16px, 파랑색으로 표시.
- 장바구니·지출·보유 물품은 앱 재실행 후 복원. 새로운 입양 세션을 시작하면 초기화.

상품 32종은 [참고 프로젝트](https://github.com/MelonJul/pet_simulator/tree/41b8eaf32658620212969345d172f6c5e32ccf5b/pet-week/dist)의
`data.js`, `price-data.js`, `items-v2.png`, `items-extra-v2.png`를 기준으로 이식했습니다.
가격은 원본의 `retail-2026-10-21` 스냅샷이고 게임 단위를 유지합니다.
원본의 시간 제한 쇼핑·추가 주문 할증은 이번 화면 구현에 포함하지 않습니다.

## 앱 내부 DB

`@op-engineering/op-sqlite`를 사용하여 Android/iOS 앱 내부에 `usee-pet-shop.sqlite`를
생성합니다. 첫 상점 진입 시 DB 스키마 버전 2를 만들고 상품 32종을 삽입합니다.
버전 1의 장바구니는 기존 데이터와 선택 상태를 유지하며 수량 제한이 없는 버전 2로 마이그레이션합니다.
`products.json`은 최초 seed용이며 화면에 표시할 상품은 SQLite에서 조회합니다.

| 테이블 | 저장 내용 |
| --- | --- |
| `products` | 상품 ID, 이름, 종, 분류, 가격, 묶음 수량, 종류, 필수 여부, 상세 정보 |
| `shop_sessions` | 입양 세션별 예산, 사용 금액, 만료 시각 |
| `cart_items` | 세션별 상품 수량, 선택 여부 |
| `inventory_items` | 세션별 보유 물품 수량 |

장바구니 변경과 구매는 SQLite 트랜잭션으로 저장합니다. 구매에서는 사용 금액,
장바구니, 보유 물품이 함께 커밋되며 오류가 나면 모두 롤백합니다.
DB 저장 성공 후 화면 상태를 바꾸며 저장 실패 문구를 표시합니다.
앱을 종료해도 유지되고, 앱 데이터 삭제 또는 앱 삭제 시 함께 제거됩니다.
서버 설정이나 별도의 DB 실행은 필요 없습니다.

네이티브 의존성이 추가되어 Android 앱 재빌드가 필요합니다. iOS는 CocoaPods
의존성 설치 후 빌드합니다. Jest에서는 네이티브 브리지만 Node SQLite로 대체하여
동일한 SQL과 트랜잭션을 실제 SQLite 엔진에서 검증합니다. 테스트 환경은 Node 24 이상입니다.

보유 물품은 구매·조회까지 연결하며 방의 기존 식사/간식/놀이 동작에 따른 재고 소비는 후속 연동 대상입니다.

검증: 타입 검사, ESLint, 상품·구매 상태 테스트, 화면에서 검색·담기·수량 변경·구매 확인 테스트.
